  SPEC CLAIM A: "768 FLOPs/edge at d=256".
    b=2 (ABELIAN / RoPE shape), OPS   = 768   REPRODUCES EXACTLY
    b=2, HOUSE                        = 1024   (1.33x the claim)
    b=4 (QUATERNION, d/4 blocks), OPS = 1792   (2.333x the claim)
    b=4, HOUSE                        = 2048   (2.667x the claim)
    VERDICT: 768 is the ABELIAN per-edge rate under OPS. The spec's
    own words say "blockwise unit quaternions at d/4 cost", which is
    1792 under the same convention. The spec prices the NON-COMMUTING
    arm at the COMMUTING arm's rate -- an M-8 carry inside the spec.

  SPEC CLAIM D: dense Cayley "~16.7M FLOPs per action type".
    d^3               = 16777216   <- what 16.7M is
    OPS   (2*d^3, inv + matmul) = 33554432  (2.0x the claim)
    HOUSE (4*d^3)               = 67108864  (4.0x the claim)
    The claim counts the INVERSE ALONE at constant 1 and drops the
    (I+Om) matmul that follows it. Under-counts by 2x (OPS) to 4x.
    AMORTIZATION: Om_a are PARAMETERS. They move once per optimizer
    step, so the build is paid |A| times PER STEP and reused by every
    edge in the batch. It is NOT per-edge. Section 4 prices it.

  6,144 REPRODUCES as: ABELIAN, ONE vector, NAIVE (no prefix), OPS.
    -> three substitutions off the arm the round headlines:
       commuting instead of non-commuting, one vector instead of q
       and k, and the naive walk the Linus gate exists to remove.
  COINCIDENCE TRAP, stated so it is not mistaken for agreement:
    depth * (b=2, OPS) = 8 * 768 = 6144
    3      * (b=4, HOUSE) = 3 * 2048 = 6144
    Both are 24*d at d=256. They agree NUMERICALLY at this shape and
    share no term. At depth != 8 they diverge; see the depth sweep.

  attention row at s=1024 d=256, HOUSE: logits-only 524288, logits + a@V 1048576
  attention row at s=1024 d=256, OPS  : logits-only 523264, logits + a@V 1046528
    524,288 = 2*s*d = the HOUSE logits row. It is HALF an attention
    row: the a @ V mix costs another 2*s*d and the spec omits it.
    The spec's ratio also mixes conventions -- 6,144 is OPS, 524,288
    is HOUSE. Held to one convention:
      HOUSE VGPE prefix per node   6144 vs logits-only    524288  ->    85.3x cheaper
      HOUSE VGPE prefix per node   6144 vs full row      1048576  ->   170.7x cheaper
      OPS   VGPE prefix per node   5376 vs logits-only    523264  ->    97.3x cheaper
      OPS   VGPE prefix per node   5376 vs full row      1046528  ->   194.7x cheaper
    DIRECTION HOLDS at every combination above. The gauge is 2 to 3
    orders below an attention row. The exact 85x is not reproduced
    by the arm the round headlines; it is 64x to 195x depending on
    convention and on whether the row is half or whole.

  The saving factor is 2*depth/3 and is depth-driven, so it is the
  same NUMBER for both gauge arms while the absolute saving is not:
    depth         factor  VGPE saved/node abelian saved/node
        2         1.333x             2048             1024

       16        10.667x            59392            29696

     1024       682.667x          4188160          2094080
  depth=1024 is the degenerate path-graph case (a chain, not a tree):
  the naive form is then O(s^2) transports and the prefix is O(s).

  --- THE LINUS GATE INVERTS ON THE DENSE PATH ---
  The gate counts COMPOSITIONS: O(n) instead of O(n*depth). That is
  a saving only if one composition costs about what one application
  costs. In the block algebra it does -- a quaternion times a
  quaternion and a quaternion times a 4-vector are the same product.
  Densely it does NOT: compose is a d x d @ d x d matmul at 2*d^3 and
  apply is a matvec at 2*d^2, so ONE composition costs d applications.
  path                 naive/node      prefix/node  prefix is
----------------------------------------------------------------------------------------------------
  blockwise b=4             32768             6144     5.333x CHEAPER
  DENSE d x d             2097152         33816576    16.125x DEARER
  Dense break-even depth (2*d^3 + 4*d^2 < 4*depth*d^2): depth = 130.
  Closed form: 2*d + 4 < 4*depth, i.e. depth > d/2 + 1, so the first
  winning depth is d/2 + 2 = 130. At the spec's depth=8 the dense
  prefix LOSES by 16.1x. THE PREFIX SAVING IS A PROPERTY OF THE BLOCKWISE
  REPRESENTATION, NOT OF THE TREE. Claiming both the dense Cayley and
  the prefix saving in one design is inconsistent.

====================================================================================================
  shuffled-gauge vs VGPE: 2441355264 vs 2441355264, difference 0
    Shuffling the label -> U_a map permutes a lookup table. It moves
    WHICH U is fetched, never HOW MANY are applied. The M5-class
    plant is EXACTLY COST-MATCHED to the treatment. Any wall-clock
    gap between arms 2 and 4 is dispatch or contention, not work.

  positional totals: abelian 3211264, VGPE 6553600, ratio 2.040816
  arm totals ratio VGPE/abelian: 1.001371  (not the pos ratio, and not
    the transport ratio -- no constant carries between the arms)
  abelian vs VGPE: 2438012928 vs 2441355264, difference -3342336 (0.1369% of VGPE total)
    per node: abelian 3072, VGPE 6144 -- the abelian arm is 2.0000x
    CAVEAT, and it is the load-bearing one for arm 3: the
    non-commutativity ablation is NOT cost-matched. It is cheaper,
    by construction, because commuting blocks are 2x2 and
    non-commuting ones are 4x4. A wall-clock comparison of arms 2
    and 3 confounds non-commutativity with block size. The FLOP
    difference is 0.1369% of the arm total, so it cannot explain a
    capability gap -- but it can explain a timing gap.
