# CEQ v17-K -- pinned environment for the Kaggle image.  Gate-0 item G0.4 (K-ENV).
#
# DERIVATION.  Not `pip freeze` verbatim.  `pip freeze` on this box lists 300+
# distributions, most of them belonging to other projects that share the
# interpreter (pytest-django, hydra, langsmith, syrupy, faraday, sigmoid ...).
# Shipping those would be a fiction about what CEQ needs.  This file is the
# *closure of the actual import statements*, walked as:
#
#   grep -rhoE "^\s*(import|from)\s+[a-zA-Z_][a-zA-Z0-9_]*" \
#       tests/arm_smprime tests/arm_pl tests/beds tests/certs tests/x35 \
#       tests/x35p tests/loop --include=*.py
#
# then followed through the `ceq.*` and `scale.*` modules those suites reach
# (ceq, ceq.beds, ceq.certs, ceq.certs.topological, ceq.hf.modeling_ceq,
# ceq.x35, ceq.x35p; scale.arm_a_k1, dispatch_count, hilbert, journal_scan,
# m3_capability, merkle, monge, planted, r10_capacity_sweep, replay_census,
# settle), then through `importlib.metadata.requires()` for the two packages
# that carry a non-obvious dependency tail (ripser, persim).
#
# Versions are read off the installed distributions with
# `importlib.metadata.version()`, on the box the suites were measured on:
# Windows 11, Python 3.11.9, torch.get_num_threads() == 20.
#
# THE CONSTRAINT THIS FILE EXISTS FOR.  Kaggle notebooks run with internet
# OFF.  `pip install` cannot reach PyPI.  So every line below is satisfiable
# only if the Kaggle base image already carries that distribution AT THAT
# EXACT VERSION.  An `==` pin is not a request; with no network it is an
# assertion about the image.  Which of these the image satisfies is NOT
# measured here -- verifying it needs a Kaggle-side probe, and this node is
# forbidden the kaggle CLI.  V17_G04_ENV.md carries the per-package call and
# tags every one of them.
#
# WHAT IS DELIBERATELY ABSENT, and why, so a reader does not re-add it:
#   triton / triton-windows -- ceq/mz_kernel.py imports triton at module
#       scope, but NOTHING in the six G0.4 suites imports ceq.mz_kernel
#       (verified: the only other mentions of the name in ceq/, tests/ and
#       scale/ are inside docstrings).  On Linux torch ships triton as its
#       own dependency anyway.  requirements.txt's `triton-windows` line
#       carries `sys_platform == "win32"`, which is False on Kaggle.
#   gudhi          -- reached only from scripts/v15_x36_probes/p05_certificates.py.
#   mpmath (direct)-- reached only from scripts/v15_x36_probes/p02_lru_lambda_range.py.
#                     (It arrives anyway as a sympy dependency of torch.)
#   psutil         -- reached only from scale/vram_gate.py and scripts/v1[56]_*.py.
#   scikit-learn (direct) -- scale/page_trend.py, scale/r10_it10_frontier.py and
#                     scale/rip_line.py import it, but none of the six suites
#                     reach those modules.  It is pinned below regardless,
#                     because ripser and persim both require it.
#   accelerate     -- colab/train_ceq.ipynb installs it; no module in this repo
#                     imports it.  ceq/hf/train.py hand-rolls its loop
#                     (torch.save of the optimizer state dict at line 269), it
#                     does not use transformers.Trainer.  Dead install line.
